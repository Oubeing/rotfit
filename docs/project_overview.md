# 项目沿革与问题档案

本文记录 RotFit 的来历、历次踩过的坑与结论，供后续维护者快速理解「为什么代码长这样」。
当前结构与用法请看 `README.md`；架构约定看 `docs/architecture.md`。

---

## 1. 项目来历

最早是为解决一个具体的标定问题：手头有两组角度观测（输入链 4 级、输出链 2 级），
知道每级的转角数值，但不知道每级**绕哪根轴**、也无从确认**叠加顺序**，
于是想「能不能用可微优化把轴和顺序一起解开」。

最初只有一个脚本（`reference/1_original_baseline.py`，即早期的 `1.py`），
后来围绕性能、兼容性、工程化分裂出 5 个版本，最终在 v0.2.0 合并为统一包，
v1.0.0 定名 **RotFit**。

---

## 2. 数学设定

- 输入侧：`R_in = R_n · … · R_2 · R_1`，每级 `R_i` 由「轴 `a_i` + 转角 `θ_i`」经 Rodrigues 得到；
- 输出侧同理：`R_out = R_m · … · R_1`；
- 损失：对探针集合 `V`，最小化 `mean_{v∈V} ‖R_in·v − R_out·v‖²`；
- 待求：全部 `a_i`（连续或离散）与叠加顺序（用 Sinkhorn 软置换参数化后取硬置换）。

---

## 3. 反复出现的核心问题：离散轴不标准

**现象**：`discrete` 模式下学到的轴往往不是严格的 ±X/±Y/±Z，而是「接近但不等于」。

**成因**（见 `docs/discrete_axes_analysis.md`）：

1. softmax 给出的是概率分布，不是 one-hot；
2. Sinkhorn 给出的是软置换矩阵，不是硬置换；
3. 两个「软」操作叠加 → 输出轴偏离标准方向。

**现有处理**（`baseline` 起采用）：

- softmax 温度降到 `0.1`，让选择更确定；
- **训练时保留软轴**（否则 `argmax` 断梯度，无法优化）；
- **推理时 `argmax` 吸附**到最近的标准轴；
- 另提供 `rotfit/utils/discrete_fix_patch.py` 作为结果后处理补丁，
  `debug_discrete_axes.py` 用于复现整条因果链。

## 4. 已修复的致命 bug（`ultimate` 变体）

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `_init_parameters()` 用 `self.config.optimizer_type == "continuous"` 判断模式，且 `mode` 未传入模型 | 连续模式参数永不创建 | 模型增加 `mode` 参数，判断改为 `self.mode`，训练入口传入配置里的 `rotation.mode` |
| 2 | `_get_rotation_axes()` 引用未定义的 `training` 变量 | 首次 forward 抛 `NameError` | 方法签名增加 `training` 参数，由 `forward` 传入 |

修复后离散 / 连续两种模式均可构造并前向（冒烟测试通过）。

## 5. 最容易误解的结论：损失很小 ≠ 结果正确

在 4 条样本 + 单探针 `[1,0,0]` 的设置下，模型会塌缩到**平凡解**：所有轴 ≈ +X。
因为绕 X 的旋转不改变 `[1,0,0]`，于是 `R_in·v = R_out·v = v` 恒成立，损失天然 ≈ 0。

数值上验证过：把全部轴强制设为 `+X` 后，重建损失与训练损失完全一致（≈1e-9），
说明模型「学会」的只是让探针不变，与真实几何无关。

**由此确立的两条实践**：

1. 训练配置必须使用**多个互不平行**的探针（`configs/multiprobe.json` 即为此准备）；
2. 结果必须用 `scripts/verify.py` 独立复核并检查轴间夹角，不能只看 `final_loss`。

## 6. 五个实现变体的定位

| 变体 | 定位 | 关键差异 |
|---|---|---|
| `baseline` | 基准 / 推荐起点 | float64、逐探针计算、`self.training` 切换软/硬轴，逻辑最干净 |
| `compatible` | 兼容性优先 | 检测 torch 版本与可选依赖，全链路 try-except 容错 |
| `optimized` | 性能优先 | float32、批量探针、数值稳定 Sinkhorn、AdamW + 早停 + 梯度裁剪 |
| `ultimate` | 工程化 | torch.compile / JIT / 混合精度 / 多优化器 / TensorBoard |
| `fixed_discrete` | 诊断工具 | 强制离散化开关 + 小样本快速试跑 + 大量打印 |

> 文档中曾给出过一组「训练时间 180s→45s→12s、内存 8.2→4.1→2.3GB」的性能数字，
> 但没有对应的测量脚本与硬件说明，**不可作为选型依据**，请以本地实测为准。

## 7. 已知遗留问题

1. `tests/` 目前为空（早期的 `test_fix.py` 是 0 字节占位）；
2. `ultimate` 的 compile/JIT 路径未做端到端验证；
3. 无固定随机种子，同一配置多次运行结果有波动；
4. `baseline` 保存的是软化后的轴，严格离散需 `verify.py --snap-discrete`。
